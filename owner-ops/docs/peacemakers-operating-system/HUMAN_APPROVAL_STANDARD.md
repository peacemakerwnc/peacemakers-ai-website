# Human Approval Standard

**ID:** `pm-os-approval` · **Version:** `0.1.0`

## Preserve existing boundaries

James must approve client-facing Blueprint delivery and consequential pilot actions (see philosophy + pilot-operating-checklist). Do not weaken these controls.

## Require explicit human approval for

Material external communications · external publishing · data deletion · production config changes · financial transactions / money commitments · contractual actions · permission/security changes · mass record changes · legal implications · significant customer impact · irreversible actions · low-confidence / insufficient-evidence actions · A4/A5 agent actions · real-client invitation sends (written authorization) · Resend/reissue of client links.

## Owner Ops today

Owner session gates all `/ops` mutations · invite send requires deliberate checkbox + ops flow · regenerate/resend are owner-only · company deletion is explicit owner procedure · no multi-approver workflow engine yet.
